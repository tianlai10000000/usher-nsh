# 交互设计规范

本文规定项目的界面与通用交互要求。新增界面遵循本文，已有界面随相关功能修改逐步调整。软件设计、编码和工程验证要求见 [开发与贡献规范](../CONTRIBUTING.md)，模块职责与状态归属见 [项目架构](../architecture.md)，具体业务流程由对应方案文档补充。

## 布局与组件

- 页面布局必须仅使用项目所采用组件库提供的布局与 UI 组件，通过组件公开的 API、组件组合和主题 token 完成配置。禁止为适配页面布局而魔改组件内部实现、绕过或破坏组件既有的布局与交互契约，也不得自行重建布局体系或重复实现组件库已有能力。
- 若现有组件无法完成布局，必须暂停该部分实现，向用户说明能力缺口、已尝试的组件用法、可选处理方案及影响，提交用户审核；待用户明确决定处理方式后，才能按批准的方案继续，禁止自行变通处理。

## 按钮加载状态

1. 按钮处于加载状态时，必须在按钮内部显示加载图标，位于文案前方，与文案一起表达正在执行的操作。不得仅使用按钮外部的加载提示替代；减少动效时可保持加载图标静止。
2. 按钮进入和退出 loading 时，宽度、高度及相邻控件位置必须保持一致。加载图标预留固定空间，按钮文案保持稳定；不得通过插入图标或更换长文案撑大按钮，也不得切换控件实现造成跳动。
3. 按钮处于加载状态时，必须设置为 disabled，禁止鼠标、键盘及其他激活方式重复触发操作。操作完成或失败后，按当前业务状态恢复可用性。

验收须覆盖加载图标位于按钮内部、加载期间禁用且不会重复执行，加载前后尺寸与相邻控件位置不变、即时切换无 loading，以及完成或失败后的状态恢复。具体模块的验证结果记录在 [批次与验收记录](todo.md)。

按钮事件必须返回其异步操作的 Promise，不能通过 `void` 丢弃完成信号。通用按钮只追踪当前视图中该次激活的生命周期；下载、安装、导出等跨视图任务继续从业务 Store 投影加载状态，不能以命令提交完成代替任务完成。同步编辑草稿、关闭浮层等操作不进入加载状态。仅含图标的按钮在加载期间以加载图标替换原图标，保持按钮尺寸与无障碍名称。

当前异步按钮统一整改不包含窗口最左侧窄菜单栏，保留其导航与更新指示器的现有行为。

加载反馈按操作语义显式启用，不能仅因处理函数返回 Promise 就显示。主题、明暗模式、控件族、语言、强调色、导航和计数等即时操作不显示 loading。文件选择与读写、主题目录扫描 / 保存、诊断导出、更新检查 / 下载 / 安装等需要等待的任务显示 loading。

## 主题与视觉配置

- 样式主题、控件族和明暗模式分别建模，通过语义 token 与组件角色连接。主题切换复用同一份 Rust 状态。
- 内置主题放在 `ui/theme/`，用户主题由本地 `themes/` JSON 加载，两者使用同一种格式并由 Rust 主题注册表解析。校验 schema、ID、基础主题、引用和取值形态，缺失变量继承 `extends` 指向的主题。视图不得按主题 ID 分支，也不在 TSX 或 Rust 中写主题色、阴影和主题名称：这些值来自主题文件，显示名称使用主题的 `names`。
- 引入外部设计体系时保存为固定提交的快照主题，在 `ui/theme/sources/` 记录映射，用脚本再生成主题文件，并在 `NOTICE` 署名。不依赖外部内部包。

## 文案与国际化

- 用户可见文案使用 `i18n/messages/` 的语义键；业务错误保存错误码和参数，展示时翻译。变更文案时同步英文与简体中文。

## 平台适配与界面降级

- 将平台差异封装在适配器及能力检测中。对不支持的控件或材质提供确定的回退，并保留已保存的用户偏好。
