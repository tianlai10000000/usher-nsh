# 交互设计规范

本文规定项目的界面与通用交互要求。新增界面遵循本文，已有界面随相关功能修改逐步调整。软件设计、编码和工程验证要求见 [开发与贡献规范](../CONTRIBUTING.md)，模块职责与状态归属见 [项目架构](../architecture.md)，具体业务流程由对应方案文档补充。

## 布局与组件

- 页面布局必须仅使用项目所采用组件库提供的布局与 UI 组件，通过组件公开的 API、组件组合和主题 token 完成配置。禁止为适配页面布局而魔改组件内部实现、绕过或破坏组件既有的布局与交互契约，也不得自行重建布局体系或重复实现组件库已有能力。
- 若现有组件无法完成布局，必须暂停该部分实现，向用户说明能力缺口、已尝试的组件用法、可选处理方案及影响，提交用户审核；待用户明确决定处理方式后，才能按批准的方案继续，禁止自行变通处理。

## 按钮加载状态

1. 按钮处于加载状态时，必须在按钮内部显示加载图标，位于文案前方，与文案一起表达正在执行的操作。不得仅使用按钮外部的加载提示替代；减少动效时可保持加载图标静止。
2. 按钮进入和退出 loading 时，宽度、高度及相邻控件位置必须保持一致。加载图标预留固定空间，按钮文案保持稳定；不得通过插入图标或更换长文案撑大按钮，也不得切换控件实现造成跳动。
3. 按钮处于加载状态时，必须设置为 disabled，禁止鼠标、键盘及其他激活方式重复触发操作。操作完成或失败后，按当前业务状态恢复可用性。

验收须覆盖加载图标位于按钮内部、加载期间禁用且不会重复执行，加载前后尺寸与相邻控件位置不变、即时切换无 loading，以及完成或失败后的状态恢复。具体模块的验证结果记录在 [批次与验收记录](todo.md)。

按钮事件必须返回其异步操作的 Promise，不能通过 `void` 丢弃完成信号。通用按钮只追踪当前视图中该次激活的生命周期；下载、安装、导出等跨视图任务继续从业务 Store 投影加载状态，不能以命令提交完成代替任务完成。同步编辑草稿、关闭浮层等操作不进入加载状态。仅含图标的按钮在加载期间以加载图标替换原图标，保持按钮尺寸与无障碍名称。

当前异步按钮统一整改不包含窗口最左侧窄菜单栏，保留其导航与更新指示器的现有行为。

加载反馈按操作语义显式启用，不能仅因处理函数返回 Promise 就显示。主题、明暗模式、控件族、语言、强调色、导航和计数等即时操作不显示 loading。文件选择与读写、主题目录扫描 / 保存、诊断导出、更新检查 / 下载 / 安装等需要等待的任务显示 loading。

## 公共控件的可用性与临时交互锁

控件必须区分业务不可用、临时提交互斥和当前操作加载，不能把共享保存状态直接作为整组控件的灰显条件。

| 输入 | 语义 | 行为与外观 |
| --- | --- | --- |
| `disabled` | 业务不可用，例如没有可移除的图片、能力尚未接入 | 拒绝操作，应用主题的禁用样式。 |
| `interactionBlocked` | 同一资源正在提交，暂时拒绝冲突操作 | 拒绝操作，保持原有静态外观，不显示加载图标、不切换控件实现。 |
| `busy` / `loadingFeedback` | 当前控件负责的等待任务 | 当前按钮内显示加载反馈并禁用，保持尺寸；不得传给无关按钮。 |

公共契约位于 `ui/components/interaction.ts`。`controlInteraction` 分别投影行为禁用与视觉灰显；`useButtonAction` 在此基础上管理当前按钮的 Promise、防重入和卸载。`ThemeButton`、`AsyncButton`、`ThemeSwitch`、`ThemeSlider` 和 `InteractionSelect` 复用该契约。值控件只适配 NSH 公开 API，不修改组件库内部。滑块的部件禁用透明度同样由业务可用性决定，不能遗漏在 `disabled:` 类中。

调用方只声明语义状态。设置、主题、背景和标题栏操作以 `interactionBlocked={appearance.busy()}` 表示同一设置资源的互斥；例如移除图片同时以 `disabled={!backgroundImage()}` 表示业务前置条件。日志未接入项继续使用 `disabled`。不共享提交资源的导航、独立操作不接入此锁。加载反馈只属于执行中的按钮或其业务任务。

NSH 适配把临时锁传入组件的行为 `disabled`，但不应用灰显样式；因此鼠标、键盘和无障碍激活仍受框架禁用语义约束。业务禁用与加载禁用的样式继续有效。调用方不得在公共控件上额外用 `disabled:` 类实现临时灰显；禁用外观应交由公共适配管理。焦点、悬停、真实值变化以及用户主动切换主题的正常视觉变化不属于“无关控件闪烁”。

AppKit 控件的 `enabled` 保留业务可用性，临时锁不调用 `setEnabled(false)`，避免系统统一灰显。平台目标动作检查 `interactionBlocked` 和业务可用性；拒绝分段或弹出选择时，恢复最后一次受控选择，不发出业务事件。无匹配选项使用原生空选择索引恢复；弹出选择器仅在有选中项时同步标题，避免标题同步把空值隐式改为第一项。按钮同样在目标动作入口拦截。原生控件在临时锁期间可能仍接收焦点或打开菜单，但选择不会提交；这与 NSH 的焦点／无障碍禁用表示不同，不宣称两者的可访问性状态完全相同。

公共组件转发 TSX props 必须保留响应式访问器。不得用对象 rest 解构或普通对象展开生成转发快照：NSH 只会继续跟踪被保留的 getter，快照会让底层控件永久读到初始 checked / value / items / 无障碍标签。适配器通过 `forwardProps.ts` 复制属性描述符并排除适配专用字段，再使用 NSH 的公开 JSX spread；行为和样式覆盖仍通过显式响应式属性传入。回归必须在同一挂载实例内验证 Switch 开→关→开、Slider 连续步进、Select 往返选择及动态标签，不能用页面重挂载掩盖属性冻结。真实 App 回归还需覆盖状态栏显隐导致的 Shell 重新布局。

连续值控件须区分“开始／继续输入”和“已接受操作的完成”。`ThemeSlider` 可以拒绝锁定后的新 `onChange`，但必须透传框架发出的 `onChangeEnd`：调用方可能在 `onChange` 中获取锁，完成事件仍需执行提交、预览清理或资源释放，不能再次以新锁状态过滤。

更新页与更新浮层共用的 `UpdateDetails` 也遵守该契约：下载期间检查入口使用 `interactionBlocked`，能力不可用和就绪前置使用 `disabled`，只有当前执行检查／下载的按钮获得自身 `busy`。更新窄菜单入口自身承担流程指示，保留其既定反馈，不把它的禁用等同于无关控件闪烁。

交互锁是表现层保护，不能替代业务并发控制。`appearance.sync` 的 `requestInFlight`、Rust 设置服务的串行提交和票据生命周期继续保留；即使从其他入口直接调用或视图尚未收到忙碌快照，也不能重复执行。完成、失败、取消或卸载均按已有操作生命周期释放锁，不能用定时器隐藏保存状态，也不能改为允许并发写入来消除闪烁。

回归分为公共控件契约与业务接入两层：公共夹具独立于业务页面验证临时锁、真实不可用、键盘与鼠标、防重入、恢复和独立操作；设置夹具覆盖状态栏、语言、外观、主题、扫描、文件选择与取消。macOS 验收分别覆盖 NSH 渲染及 AppKit 目标动作，并对测量得到的控件区域、设置内容区域做 PNG 解码像素比较：临时锁前后应一致，真实不可用应产生禁用反馈。可控延迟是视图边界夹具，不代表真实磁盘延迟或跨平台验收。执行状态与证据在 `todo.md`，问题索引在根目录 `bug-history.md`。

## 主题与视觉配置

外观选项按“跟随系统、浅色、深色”排列，NSH 与 AppKit 共用 `ui/config/appearance.json` 的顺序。标题栏按保存的偏好循环切换，图标表示当前保存的偏好（跟随系统为显示器、浅色为太阳、深色为月亮），悬停提示与按钮无障碍名称表示下一步目标；深色之后回到跟随系统，不以系统当前实际明暗决定偏好。所有入口继续通过同一设置 Store 提交。

- 样式主题、控件族和明暗模式分别建模，通过语义 token 与组件角色连接。主题切换复用同一份 Rust 状态。
- 内置主题放在 `ui/theme/`，用户主题由本地 `themes/` JSON 加载，两者使用同一种格式并由 Rust 主题注册表解析。校验 schema、ID、基础主题、引用和取值形态，缺失变量继承 `extends` 指向的主题。视图不得按主题 ID 分支，也不在 TSX 或 Rust 中写主题色、阴影和主题名称：这些值来自主题文件，显示名称使用主题的 `names`。
- 引入外部设计体系时保存为固定提交的快照主题，在 `ui/theme/sources/` 记录映射，用脚本再生成主题文件，并在 `NOTICE` 署名。不依赖外部内部包。

## 文案与国际化

- 用户可见文案使用 `i18n/messages/` 的语义键；业务错误保存错误码和参数，展示时翻译。变更文案时同步英文与简体中文。

## 平台适配与界面降级

- 将平台差异封装在适配器及能力检测中。对不支持的控件或材质提供确定的回退，并保留已保存的用户偏好。
